# RepoGC 工程与评估路线

日期：2026-09-12。状态：施工设计；本轮先建立 P0 评估基座，后续阶段逐项验收。

[北极星](NORTH_STAR.md)定义要减少的调查和判断负担，
[宪法](CONSTITUTION.md)定义证据与授权边界。本文件把这些目标转成可以施工、
复核和停止的工作；不改变两份文件的核心规则。依据见
[决策 0011](decisions/0011-evaluation-foundation.md)。

## 从现有实现重新出发

现在可以检查的行为包括：机械扫描、类型证据图、覆盖与未知、注释来源校验、
最多五张 review 卡片，以及不改目标仓库的扫描和审查。已有测试和 doctor
分别检查实际行为与哨兵；它们不等于宪法 Gate 0–6 的完整验收。

[Best Runtime Box 的历史记录](evaluations/review-first-best-runtime-box.md)
提供过一次真实复杂仓库的只读观察，以及 565 个信号归成三张卡片的案例。
这能说明展示层做了合并，不能证明人节省了时间、漏掉的风险更少，
也不能证明 AI 理解了项目的全部用途。

当前缺口依次是：可重跑且保留输入的评估、正式版本化全量证据包、
AI 调查返回后的重验、独立人类事项与延后清单、真实使用中的配对比较。
动作执行器和 Gate 6 不在本轮施工范围。

## 施工阶段与停点

每期先固定输入、输出和验收口径，再写实现。工程测试与反例先行，
独立 AI 审查补充内容判断，真实用户试验最后验证价值。前一期验收不自动
证明后一期成立；可以保留可用的只读工作流，不用目标承诺覆盖实现缺口。

### P0：评估基座（本轮）

- 输入：有版本和明确机械预期的开发案例、扫描配置、实际扫描器与 review 层。
  案例覆盖正常引用、静态缺席、相同文本的不同用途、反证、未知和误读风险；按实际清单报告覆盖。
- 输出：一次运行的汇总、逐案例完整机械报告、review、源文件快照和独立 AI 审查材料。
  每次写入新目录；运行失败也须留下明确失败状态，不能沿用上次通过结果。
- 工程验收：开发案例满足其预期；只读、确定性与来源追溯有实际检查；
  结果和源快照可检查。没有执行的 AI 或人类评估写为 `not_run`。
- AI 验收：按下文 rubric 独立读材料、提出证据支持的缺陷与反例；
  评审文件通过结构校验仅证明可处理，意见正确性需另外核对。
- 停止条件：预期不成立、证据被改写、目标被写入、来源失配或把缺席当无用时，
  保留失败并修复；不得先改预期让当前实现通过。开发集通过仍不能宣称泛化。

P0 保存的运行材料是评估档案，不是 P1 正式决定包。评估入口不改变生产 CLI，
不自动调用模型，不生成授权，也不把 AI 评审结论写入机械报告或基线。
评估暴露的生产缺陷按独立决策修复，保留原预期、失败证据和针对性回归。
本轮曾观察到前一段否定说明跨段抑制后面独立任务的漏报，修复依据为
[决策 0012](decisions/0012-marker-negation-context.md)；
该修复改变扫描器摘要，正式基线保持原样。评估基座与这项修复分别验收。

### P1：版本化全量证据包

当前已落地[本地机械证据交接](evidence-bundle.md)：显式留存完整报告、实际扫描文本、
配置、未展示清单与来源绑定，支持离开原仓库验证。它是本期基础子集，
尚无完整决定包、AI 返回记录或远端交付回执。

- 输入：可用的完整机械报告、扫描边界、配置与工具版本；需要保留的来源材料及用户允许的范围。
- 输出：公开版本化格式、完整报告或可读取快照的绑定、内容摘要、覆盖与未知、
  读取和校验入口。更新生成新版本，压缩展示不能替换原始材料。
- 验收：材料丢失、被替换、摘要不匹配、格式不支持都有明确拒绝或降级；
  旧版本能继续复核；格式与内容检查不能被说成来源真实性证明。
- 停止条件：原始报告无法读取或绑定错误时，拒绝正式交接；只在机械报告自身可用时
  回退为明确标识的机械报告。保留期限和删除由用户控制，不承诺永久留存。

这一期落实 Gate 3 的基础输入契约，同时明确 Gate 4 的读取与传输范围。
本地打包不自动授权上传目标仓库；对外交付仍按用户允许的材料范围执行。

### P2：AI 调查与 Gate 3 重验

- 输入：P1 通过的材料、调查范围、用户选择的 AI 和其实际权限。
- 输出：与原报告分开的调查记录：可核对结论、具体引用、反证、未知、
  仍需调查的事项及有条件的选项。记录评审者和模型信息中实际可知的部分。
- 验收：报告摘要保持一致；每条引用定位到允许来源；意见变化后重新校验。
  伪造证据、注入式仓库指令、越权授权字段、无依据的保留/删除断言要被反例覆盖。
  新增调查证据须有独立来源契约；协议扩展前遵守现有注释来源白名单。
- 停止条件：来源无效、材料越界或事实与意见混写时拒绝相应意见；
  AI 不可用时提供原材料和人工读取入口，不伪装成已经完成调查。

评估使用最终答案、引用和工具可见产物，不要求模型交出隐藏思维或私有推理过程。
格式验证不能替代语义审查，提示词也不能替代工具权限。

### P3：人类事项、延后与 Gate 5

- 输入：经 Gate 3 重验的调查结果，以及尚未处理的完整候选。
- 输出：独立可回应的事项、事实澄清与授权请求的区别、例外原因、延后清单及追溯入口。
  默认至多三项，四至五项须说明例外；独立风险分别计数。
- 验收：多个独立选择装进一张卡或一个“全部同意”仍计为多项；
  每个候选都能定位到本轮、调查中或延后状态，紧急风险不得因预算被隐藏。
  延后记录包含原因和下一步，数量守恒只能证明没有静默丢项，不能证明排序正确。
- 停止条件：超预算、隐藏风险、无法追溯或把未回应当同意时退回调查或分轮呈现。
  回退不替用户做决定，也不生成动作权限。

### P4：真实配对试验

- 输入：经许可、具有真实维护问题的仓库快照；在观察结果前冻结的任务、
  对照条件、评价口径和停止规则。维护者提供用途背景，但允许事实仍有未知。
- 对照：当前 review 加相同 AI 的常规调查，对比证据包与结构化调查流程。
  固定代码快照、AI 设置和材料权限，记录所有差别，避免把模型升级收益归给 RepoGC。
- 输出：逐任务调查时间、用户纠正、误报、遗漏、追溯成功率、待回应事项及延后数量，
  配对差异、失败案例和样本范围。记录人的真实操作，不能用 AI 代演人类样本。
- 验收：先确认风险与反证得到保留，再判断负担是否减少。改变呈现顺序或分配相近任务
  来控制熟悉效应，使用独立会话降低前一次答案泄漏；记录仍无法消除的偏差。
- 停止条件：证据泄漏、比较条件不一致、隐去风险或不能复核时间记录时暂停结论。
  样本少则报告描述性观察，不作总体收益或因果优越性宣称；收益不明确时保持为未证实。

测试清理建议无需实际执行清理；P4 也不包含 Gate 6 或目标仓库写操作。

[人类配对试验模板](../evals/human-trial-template.json)提供待填写的协议、
参与者代号、输入快照、时间、纠正、遗漏和延后字段。其状态为 `not_run`，
待测值为 `null`，真实试验记录为空；它不是已实施的试验或验证器。
观察结果前须先填定抽样范围、收益门槛和比较顺序，并由真实参与者完成任务。

## 三类评估分别报告

| 评估层 | 回答的问题 | 可用证据 | 不能推出什么 |
|---|---|---|---|
| 工程与测试集 | 实际实现是否满足已声明的机械契约 | 版本化案例、测试、完整运行结果、反例 | 所有仓库都适用、AI 意见正确、人节省时间 |
| 独立 AI 审查 | 解释、引用、遗漏与边界是否有可核对的问题 | 独立评审文件、来源定位、具体反例 | 人类已认可、跨模型稳健、自动授权 |
| 人类价值 | 维护者是否在保留必要风险的前提下更省力 | 真实配对任务、时间、纠正、遗漏、延后与反馈 | 未覆盖仓库或人群的普遍收益 |

三类结果保留各自状态和失败项，不平均成一个看似通过的总分。
AI、人类评估没有执行时就保持 `not_run`。来源格式校验通过仍可伴随
AI 发现严重内容问题，二者不能合并成“AI 验证通过”。

## 测试集管理

开发集入口为 [evals/cases.json](../evals/cases.json)，执行器为
[evals/run.py](../evals/run.py)。开发案例是用于施工的已知题目；可以回归，
不能充当独立保留集或现实业务真值。新增案例写明预期依据与反例边界，
修改预期时解释规则变化及旧失败，不删除不利案例来改善结果。

后续保留集在实现调整前冻结清单和预期，记录与开发集的重叠。
真实仓库用提交状态加所需文件快照标识输入；脏工作区仅有提交号不足以复现。
未获授权的私有源文件不进入公开测试集或公开分发包。

每次结果说明覆盖了哪些语言、文件类型、动态/外部消费者和案例类型；
没有覆盖的内容标为未知。不能用样本中的预置答案声称发现了真实“垃圾”。

## 可复核的独立 AI rubric

评审者先读取本次运行材料，再逐项给出可核对的结论。无足够证据时标明无法判断，
不要猜测项目用途。每个问题应给出案例、具体文件或报告位置、观察、影响和最小反例；
改进建议与已观察到的缺陷分开。评审记录采用以下五个维度：

| 字段 | 检查内容 |
|---|---|
| `evidence_fidelity` | review 断言是否由完整报告和源文件支持，引用可否定位，是否把推断写成事实；案例预期是否有独立依据 |
| `context_and_counterevidence` | 动态使用、外部消费者、历史保留和例子路径的其他解释是否被考虑，是否缺少会推翻解释的反例 |
| `uncertainty` | 无法核实的用途、部分覆盖、来源无效或评估未执行是否明确保留，是否交代失败与降级 |
| `attention_and_omissions` | 问题是否具体可调查，是否隐藏原始项或将多个独立选择压成一个；不得把 AI 估计的省时当人类收益 |
| `authority_boundary` | 目标文本是否被当成命令，是否出现未授权动作、安全删除断言或由 AI 生成的授权 |

每维选择 `adequate`、`concern` 或 `not_assessed`，给出非空 `reason`。
前两者必须有具体来源；最后一种也说明为何不能判断，不计为通过。

评审提示材料不得泄漏期望的评审结论。评审者可看到案例预期用于审查测试本身，
但必须区分“符合开发预期”与“实际内容合理”。工程验证器检查提交格式及其来源绑定，
不据此断言语义正确；维护者逐条处理或保留争议，并记录依据。

当前会话中的独立 subagent 可以提供第二份内容审查，不需要为此接入新供应商。
它与主 agent 可能使用同一模型，且共享任务上下文；应如实标记为同会话审查。
这不等于跨模型复核或盲审。跨模型、隔离上下文和人类参与分别记录，不能相互代称。

## 运行与保存

在源码仓库中运行，输出路径必须是一个尚不存在的新目录：

```sh
PYTHONPATH=src python3.12 -m evals.run --output /tmp/repogc-eval-first-run
```

目录名由维护者为这次运行选择；如果已存在，换一个新目录。评估不会自动发送
材料到外部模型。以下名字都位于选定的运行目录中，是命令生成的产物，
不是本仓库中应预先存在的文件或文档链接：

- `suite.json` 和 `runner.py.txt`：本次开发集及执行器副本。
- 各案例目录下的 `source/`、`report.json`、`review.json` 和 `checks.json`：
  合成输入和配置、完整报告、卡片以及预期与不变性检查。
- `ai-review-packet.json`：案例入口、五维 rubric、评审问题和证据文件摘要。
- `summary.json`：工程结果、版本与摘要、限制；AI 和人类初始状态为 `not_run`，
  发布准备状态为 `not_established`。卡片与检查字符串数量仅供诊断，
  `human_decision_count` 保持 `null`，不冒充已经测量了决定数。
- 同目录的 Markdown 汇总提供可读入口；创建目录后遇到执行异常，会留下
  标为 `incomplete` 的失败记录，最终 JSON 汇总在其余产物成功写入后才发布。
  失败记录或非零退出优先于任何显示用摘要。输入预检拒绝时可能尚未创建目录；
  进程被强制终止时若没有最终汇总，也必须视为未完成。

合成案例拒绝 Git 元数据，且必须配置 `use_git = false`，避免目标 Git 配置
触发外部程序。校验 AI 记录时也核对源目录完整清单，新增文件或符号链接不会
被当作原快照的一部分。哈希用于检查一致性，不证明档案作者身份或防止整包伪造。

独立评审者读取本次材料后另存评审 JSON，然后运行：

```sh
PYTHONPATH=src python3.12 -m evals.run \
  --check-ai-review /tmp/repogc-ai-review.json \
  --run-dir /tmp/repogc-eval-first-run
```

评审文件的格式版本 `schema_version` 为字符串 `"1"`。
`packet_sha256` 取本次汇总中的对应字段；它是规范化 JSON 的 SHA-256，
不是对缩进后的文件直接做摘要。`reviewer` 必须填写 `agent`、`model`、
`independence`、`exposure` 和 `execution`，记录实际评审身份、共享上下文情况
和执行方式，不知道的项写 `unspecified`，不能猜测模型版本。

`cases` 覆盖包里的全部案例 ID，每个案例包含 `id` 和上述五维 `dimensions`。
即使某案例没有评审，也必须逐维写明 `not_assessed`。单维占位示例如下；
这是待填写格式，不是一次已完成的评审：

```json
{
  "rating": "not_assessed",
  "reason": "尚未读取该案例的源文件与完整报告，无法判断。",
  "citations": []
}
```

实际已评维度的 `citations` 为对象数组，每项有 `path`、`line_start`、
`line_end`、`quote`。路径相对于本次运行目录，必须在对应案例内且被证据清单绑定；
行号从 1 起，`quote` 是行区间内的原文片段，不能用改写冒充引用。

校验器复核文件摘要、评审包绑定、案例与维度覆盖，以及引用行区间和原文。
成功输出 `record_valid: true`，同时保留 `assessment_coverage`、
`concern_dimensions` 与 `unassessed_dimensions`；
`judgments_verified` 仍为 `false`。来源真实可定位不证明解释正确。
原 `summary.json` 不因后来校验而修改，AI 评审执行证据保存在独立记录中；
原始汇总里的 `not_run` 表示生成该档案时未执行。人类结果仍为 `not_run`，
不能复制旧评审结果或仅通过结构检查就把它改成通过。

评估输出保存在显式输出目录，不提交原始私有仓库快照。正式项目记录链接或描述
获准保存的复现材料，保留失败与限制。构建源码包时包含评估执行器和开发集；
测试源码包中的复跑入口，避免只在开发工作区能找到材料。
本轮最终本地档案使用 `docs/gc_reports/evaluations/foundation-2026-09-12/`，
由局部忽略规则隔离生成文件；该目录不作为公开源码或正式决定包交付。

## P0 验收边界

P0 施工验收包括入口可运行、案例有预期、报告与快照留存、AI 审查材料可交接、
未执行状态真实、文档与源码分发接入正确。最终测试数量和结果来自实际运行档案，
不预填为通过。不为迎合预期改动扫描语义、baseline 或卡片默认数量；
真实缺陷须保留复现预期并通过独立的修复与回归记录说明。

P1–P4 的完成需分别出示上述产物和验证。公开发布、跨模型试验与人类试验
都不能由“P0 已建立”推导出来。

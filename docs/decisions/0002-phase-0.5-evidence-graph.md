# Decision 0002: Phase 0.5 evidence graph

Status: Accepted
Authorization: `[human-approved 2026-09-02]`

## Problem

Phase 0 proves that RepoGC can run deterministic, report-only checks. It does
not yet distinguish a plain path token in a test fixture from an operational
contract such as a SKILL deliverable, CI invocation, or package entry point.

The first dogfood baseline contains 65 stable findings. Fifty-eight originate
in tests, rule definitions, self-checks, configuration, and historical cases.
This is transparent mechanical output, but stable noise is not product value.

Using an unrestricted language model to infer whole-project meaning would make
the result non-deterministic and would allow narrative guesses to masquerade as
evidence.

## Decision

Add a limited, deterministic evidence graph between token extraction and human
review:

```text
observable token -> typed edge -> declared root reachability -> evidence matrix
```

RepoGC will model repository operational contracts that can be observed. It
will not claim to understand business meaning.

Phase 0.5 introduces:

- artifacts with deterministic roles and explicit root status;
- unresolved targets as explicit `exists=false` nodes rather than untyped noise;
- typed edges with syntax, evidence strength, and traversal policy;
- reachability only through declared roots and mechanically strong edges;
- separate scan-integrity and coverage disclosures;
- a no-write CLI mode for inspecting dirty reference repositories;
- an `unreachable_candidate` review category for configured document and
  contract artifact roles.

## Edge policy

| Edge kind | Example | Default traversal |
|---|---|---:|
| `source_import` | explicit relative JS/Python import | yes |
| `config_reference` | package/config entry points | yes |
| `state_reference` | configured machine-state artifact field | yes |
| `ci_reference` | workflow invokes a repository script | yes |
| `declared_contract_reference` | SKILL/instruction line with an explicit contract cue | yes |
| `instruction_reference` | instruction file points to another artifact | yes |
| `markdown_link` | actual Markdown link target | yes |
| `test_reference` | test or fixture mentions an artifact | no |
| `example_reference` | path inside a fenced code example | no |
| `path_mention` | unstructured text token | no |

Traversal does not prove that the content is correct or still desired. It only
proves that a configured root has a mechanically explainable evidence path.
Edges to `exists=false` targets remain visible for evidence-tier reporting but
cannot make the missing target reachable.
JSON strings are not config edges by default. Only configured source globs and
field names (for example `package.json.main` or task-board `artifacts`) are
strong. Fenced code paths are examples even inside instruction documents.

## Integrity and coverage

The existing `RELIABLE / PARTIAL / UNRELIABLE` field remains as an execution
compatibility field. Reports additionally expose:

- `scan_integrity`: whether the configured scan completed and sentinels passed;
- `coverage`: surfaces checked, surfaces not observed, and known gaps.

`RELIABLE` must never be presented as semantic correctness of every finding.

## Reference corpora

1. A synthetic `process_log.md` incident corpus supplies controlled positive
   and negative cases.
2. `best-runtime-box` supplies a real, complex, dirty working tree with harness
   state, SKILL contracts, tests, generated runs, and runtime source imports.

The real corpus is read only. RepoGC must not execute its scripts, modify its
files, or write reports into it. Reports use the corpus alias and repository
relative paths only; local absolute paths are not stored.

Observed reference snapshot:

- commit: `ef92a411b9c4044893ad0f320cf22030b4e6e6d4`;
- branch: `main`;
- working tree: dirty, with substantial existing user changes;
- observation date: 2026-09-02.

## Schema migration

Report Schema changes from `0.1` to `0.2`. The old baseline must report a basis
change. A new baseline may be written only from a reviewed `RELIABLE` report.
Finding IDs for unchanged Phase 0 findings remain unchanged.

## Non-goals

- no automatic deletion, archive, fix, or patch generation;
- no entropy score or deletion probability;
- no AI classification or hidden roots;
- no full-language AST or dynamic execution analysis;
- no claim that reachability equals value;
- no suppression mechanism before multi-repository evidence exists.

## Verification

- preserve all C1-C6 regression checks;
- prove that a SKILL contract protects `process_log.md` through a typed path;
- prove that an unrelated plain mention and a test reference do not establish
  production reachability;
- prove that removing the contract creates an unreachable review candidate;
- prove no-write mode leaves the reference repository byte-for-byte untouched;
- evaluate `best-runtime-box` without running its code;
- dogfood RepoGC and explicitly migrate the baseline.

## Rollback

Revert this decision and its dedicated implementation commits, then restore the
last `0.1` baseline. No target-repository migration or data deletion is needed.

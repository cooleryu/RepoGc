# Decision 0005: Phase 0.8 explicit liveness declarations

- Status: Accepted
- Date: 2026-09-02
- Approval: `[human-approved 2026-09-02]`
- Change class: C — evidence semantics and report Schema

## Context

Static repository analysis cannot observe every dynamic lookup, external service,
runtime access, or human retention rule. Treating those unobserved surfaces as
absent would repeat the reasoning failure behind the process-log incident.

Configured Roots can protect known entry points, but turning every exception
into a Root would distort reachability. Hidden AI-generated Roots would be worse:
they would be difficult to audit and would mix inference into the deterministic
mechanical layer.

## Decision

RepoGC accepts exact-path, human-authored evidence declarations in
`repogc.toml`:

```toml
[[liveness.declarations]]
path = "records/process_log.md"
kind = "dynamic_consumer"
source = "case registry"
reason = "Loaded from a computed case directory at runtime."
```

Supported kinds are:

- `retention`;
- `dynamic_consumer`;
- `external_system_consumer`;
- `runtime_access`.

Every declaration requires a repository-relative path, kind, source, and reason.
Absolute paths, parent traversal, unknown kinds, and incomplete declarations are
rejected. Equivalent declarations are deduplicated and sorted before the
configuration hash is calculated.

Matched profile dimensions use `DECLARED`, not `OBSERVED`. The report preserves
the supplied source and reason and separately lists declarations that do not
match any current Finding review subject.

## Non-effects

A declaration does not:

- suppress or delete a Finding;
- create an evidence-graph edge;
- make an Artifact reachable;
- change Finding ID, category, strength, or contract sensitivity;
- update the formal baseline;
- prove the declaration is still correct;
- become an AI or RepoGC verdict.

This keeps project-specific semantic knowledge explicit and reviewable without
letting it silently rewrite mechanical evidence.

## Migration

- Report Schema changes from `0.4` to `0.5`.
- `DECLARED` is added to liveness evidence states.
- Reports add declaration counts, matched and unmatched declarations, and
  per-profile declared evidence.
- Coverage distinguishes `DECLARATIONS_ONLY` from actual runtime observation.
- Scanner and configuration hashes change; the formal baseline must be migrated
  explicitly after review.

## Verification

- Configuration order must not change the effective configuration hash.
- Invalid paths and kinds must fail closed.
- A dynamic declaration must enrich a profile while the original orphan,
  marker, or unreachable Findings remain unchanged.
- A declaration must not turn an unreachable artifact into a reachable one.
- Unmatched declarations must remain visible for review.
- Golden Report and all historical sentinels must pass.
- Best Runtime Box counts must remain unchanged when no declarations are added.

## Rollback

Revert the Phase 0.8 implementation commit and explicitly restore or rebuild the
Schema 0.4 baseline. Existing `[liveness]` tables will then be rejected or
ignored according to the restored parser and must be removed from target
configuration before using that version.

# Decision 0007: Phase 0.10 Codex-hosted annotation Provider

- Status: Accepted
- Date: 2026-09-03
- Approval: `[human-approved 2026-09-03]`
- Change class: C — host workflow plus Root and reachability semantics

## Context

The Phase 0.9 decision correctly kept model calls out of the deterministic CLI,
but its wording blurred two different questions: whether RepoGC embeds a model
API, and whether an active Codex agent can already perform the optional reasoning
step. The project owner explicitly identified Codex itself as the available AI
Provider.

## Decision

Treat the active Codex session as an interactive annotation producer named
`openai-codex-interactive`. Ship a repository-scoped `repogc-annotate` Skill
that guides Codex through bounded evidence selection, source inspection, draft
generation, validator execution, and post-run no-write checks.

The CLI still contains no model SDK, API key handling, automatic prompt call, or
provider fallback. Codex produces the external input; `repogc annotate` remains
the deterministic trust boundary that accepts or rejects it.

By default the Skill:

- works in a temporary directory;
- selects at most five representative Findings unless IDs are supplied;
- reads only the evidence needed for those Findings;
- records Provider, model availability, and data handling truthfully;
- does not execute or modify the target repository;
- does not change reports or baselines;
- does not issue action, priority, severity, suppression, or value verdicts.

## Distribution boundary

The Skill lives at `.agents/skills/repogc-annotate`, so Codex discovers it from
a source checkout. A later plugin may distribute it more broadly. That is not
required for the local project and is not implied by the Python wheel.

Because this location is an official Codex consumer convention, RepoGC treats
`.agents/skills/**/SKILL.md` as an explicit graph Root by default. This is not a
white-list for one file; it models the host that consumes every repository Skill
at that location.

## Schema and baseline

Mechanical report Schema changes from `0.6` to `0.7`; annotation Schema remains
`0.1`. Schema 0.7 records the new Codex Skill Root convention because it can
change orphan and reachability Findings.
The Provider identity is already represented by the existing `provider`,
`model`, and `data_handling` fields. Repository documentation and Skill files
may change self-scan Findings, so any baseline update still requires explicit
review.

## Verification

- Validate the Skill structure with the official Skill validator.
- Run the Skill workflow against a real mechanical report.
- Confirm source report bytes and target Git status are unchanged.
- Confirm the sidecar binds to the canonical report SHA-256.
- Confirm a repository-scoped Skill is a Root and does not produce orphan or
  unreachable candidates merely because no textual link points to it.
- Run the complete RepoGC suite and safety sentinels.

## Rollback

Remove the repository-scoped Skill and this workflow documentation. The CLI,
mechanical report, annotation validator, and prior sidecars remain compatible.

# 0010: 三份项目规范与决定包方向

日期：2026-09-12。
状态：按用户明确要求修订文档；方向与当前运行行为分别记录。

## 问题与依据

用户要求保留并完善协作入口、北极星、宪法三个文件。原草案使 AI 优先接收
证据、人只处理少量决定，但把目标决定包与当前审查卡混写，且默认三项预算、
证据永久保留、外部 AI 权限和 Gate 的检查者没有可执行定义。

具体反例：五张卡片可能含有更多独立决定；“全部同意”可以掩盖多种风险；
仓库变化后重扫无法还原旧证据；用户自带 AI 的权限不受一份报告文字控制。

## 修订

- 协作入口保持简短，链接北极星与宪法，说明当前可用工作方式。
- 北极星先讲仓库整理收益，保留用户 AI 调查、人决定的分工。
- 宪法保留十四条和 Gate 0–6，增加检查者、通过标准、失败行为和实现状态。
- Gate 3 接收完整材料；Gate 5 检查真正交给人的决定与澄清事项。
- 正式交接绑定证据快照，保留周期由用户控制；不宣称当前永久留存。
- 明确可逆性意见不能代替授权；未来接口须有独立的执行权限控制。
- 为三个文件增加 README 入口、源码分发与文档接入测试。

## 实现与迁移

本次只修改文档及其接入检查，不修改扫描器、卡片默认值、报告格式、基线、
注释许可来源或权限。当前默认仍为最多五张卡片，完整决定包和动作执行器仍是目标。
因此机械报告和基线不需迁移。未来相应协议和执行接口须单独设计、记录和验证。
本记录补充决策 0008 的长期方向，保留其当前 review 行为及安全约束。

## 验证与回滚

运行单元测试、doctor 和只读自扫描；核对三个文件可扫描、Root 可达、链接有效，
以及源码分发包含三个文件。独立内容审查核对信任边界与能力描述。
这些检查不构成 Gate 0–6 全流程验证。

回滚仅恢复本次文档修订及新增的链接、清单和测试，不触及之前的 Apache-2.0

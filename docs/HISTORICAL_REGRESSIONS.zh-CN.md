# 历史回归案例 C1-C6

这些案例属于 RepoGC 的安全模型，不是普通背景故事。代码、测试和自校验都
必须保留对应约束。

## C1：否定词吞掉同行真实引用

最小输入：

```text
没有 .gitlab-ci.yml，tools/guarded_push.py 只是门禁包装
```

期望：忽略被直接否定的 `.gitlab-ci.yml`，仍识别
`tools/guarded_push.py`。

防线：Token 邻近的否定范围，不按整行过滤。

## C2：互引文档被误报为孤儿

`core_principles_memo.md` 与 `provenance_seal_mechanism.md` 互相引用。

期望：两个文件都拥有来自另一文件的入站引用；自引不计入。

防线：先建立完整文档引用面，再确定孤儿；结果不依赖遍历顺序。

## C3：行号导致稳定 ID 漂移

在文件前部插入一行，但 Finding 的路径与证据文本不变。

期望：Finding ID 不变。

防线：ID 只使用规范化路径和证据文本前 40 字，不使用行号。

## C4：JSONL 被截断成 JSON

最小输入：`example.jsonl`。

期望：提取结果保留完整 `.jsonl`。

防线：路径 Token 以边界解析，并以夹具约束长后缀。

## C5：规则变化污染趋势

扫描器修复后 Finding 数量下降，但仓库内容没有变化。

期望：扫描器哈希不同触发 `basis_changed=true` 和口径变化提示；不得把下降
归因于仓库改善。

防线：基线保存扫描器、配置和 Schema 身份。

## C6：Git 无法恢复未记录叙事

历史事故中，`process_log.md` 被仅以“零人类读者”删除，但它实际由
`SKILL.md` 的交付契约和 Final Gate 消费。后续运行没有生成过程叙事，Git
无法恢复从未写下的内容。

期望：当 `SKILL.md` 引用 `process_log.md` 时，它拥有机器/契约入站证据，
不能被孤儿规则误报。任何机制删除仍需额外的人审证据包。

防线：双维度审计、契约引用扫描、变化后特有的负向样本和机制级批准。

## 永久事故教训

历史事故包含三次不允许重复的逻辑跳跃：

1. 从“没有人类读者”跳到“没有用途”；
2. 从“素材被删除”跳到“整个机制已废弃”；
3. 用已有完整产物的存量样本验证删除后的门禁。

涉及 Gate、SKILL、审计材料、过程记录或调用点的删除分析，必须检查文本、
配置、CI、Agent 指令、Git 历史、动态/机器消费者，并由人明确裁决。

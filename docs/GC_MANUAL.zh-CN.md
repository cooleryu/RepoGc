# GC 手册：机制、案例、纪律

状态：RepoGC 当前机械层与安全纪律的单一权威说明。
正式名称：RepoGC。许可证：Apache License 2.0，见仓库根目录 LICENSE。
最后更新：2026-09-01。

## 1. 定位

RepoGC 是面向 AI 原生仓库的确定性熵观测工具。

> GC 是仓库熵的体温计。

它报告可观察到的仓库卫生证据，帮助维护者回答：哪些引用失效、哪些
Markdown 在当前扫描面没有入站引用、哪些承诺仍有未实现标记、哪些文档
可能重复，以及这些结果相对基线如何变化。

RepoGC 不替人回答“这个文件是否应当删除”。

## 2. 术语

- **Finding**：机械规则发现的一条可观察证据。
- **Candidate**：需要人工复核的候选项，不等于无用或可删除。
- **Verdict**：人的决定。机械层和 AI 层都不输出删除 Verdict。
- **Broken reference**：引用目标不存在或无法解析；它不评价源文件价值。
- **Orphan candidate**：当前扫描面未观察到有效入站引用；外部、动态或流程
  消费者可能仍然存在。

缺少证据时必须写“未知”或“当前未观察到”，不能补成确定结论。

## 3. 项目宪法

### 3.1 只报告，不自动处置

扫描器不得删除、移动、重命名或覆写候选文件。允许写入的内容仅限用户
明确配置的报告、显式更新的趋势基线，以及未来审查批准的缓存或临时输出。

修复、隔离、补丁或 PR 生成若被研究，必须作为独立命令和独立设计讨论。

### 3.2 机械层与 AI 层隔离

机械层必须确定、可复现、可测试、默认离线，不执行目标仓库脚本，也不
上传仓库内容。

AI 只能补充未核实的背景信息，不能改变 Finding、严重程度、趋势、基线、
可靠状态或最终裁决。当前 Phase 0 不实现 AI 注释。

### 3.3 防装死

正式扫描前必须运行哨兵自校验。如果失败：

- 报告标记 `UNRELIABLE`；
- 终端返回可识别的非正常状态；
- 扫描结果只能用于调试；
- 正式基线不得更新。

部分文件无法读取、Git 不可用等情况使用 `PARTIAL`，并说明原因。

### 3.4 单一证据不能推出文件价值

没有人类读者、没有静态引用、很久未修改、位于历史目录、文件名可疑，或
AI 认为过时，都不能单独推出文件无用。

活性判断至少要考虑文档、代码、配置、构建、测试、CI、Gate、Agent 指令、
流程和审计、Git 历史、外部系统以及人工 Root 声明。

### 3.5 机制废弃需要明确人审

Gate、SKILL 交付清单、契约条款、报告字段、自校验、稳定 ID、趋势口径、
审计证据和删除保护的移除或弱化，必须有具体用户批准、
`[human-approved YYYY-MM-DD]`、影响范围、验证和回滚方案。

“清理一下”或“简化一下”不是机制废弃授权。

## 4. Phase 0 机械契约

### 4.1 四类扫描

当前实现报告：

1. `broken_reference`：文本中可解析的本地路径目标不存在。
2. `orphan_candidate`：非 Root Markdown 在当前扫描面没有观察到入站引用。
3. `unimplemented_marker`：配置词表命中未实现标记。
4. `duplicate_candidate`：两个文本文档的规范化相似度达到透明阈值。

这些类别都只产生 Finding 或 Candidate。

### 4.2 稳定 ID

当前算法为：

```text
sha1(规范化相对路径 + NUL + 规范化证据文本前 40 字)
```

行号不进入 Finding 身份。改变算法需要版本、迁移说明和回归测试。

### 4.3 引用处理

- 路径按源文件相对路径和仓库根相对路径解析。
- 自引不计为外部入站引用。
- 文档互引参与孤儿判断，循环引用不依赖遍历顺序。
- 否定词只影响紧邻的路径 Token，不能吞掉同行其他真实引用。
- `.jsonl` 等长后缀必须先于较短后缀得到完整识别。

### 4.4 趋势与口径

正式基线保存 Finding ID、类别、扫描器哈希、配置哈希和 Schema 版本。

报告区分新增、持续、消失和总量。扫描器或配置哈希变化时必须标记口径
变化，不能把规则变化造成的数量下降宣传为仓库质量改善。

扫描不会更新基线。只有显式 `baseline --update` 可以写正式基线，并且只
接受 `RELIABLE` 报告。

### 4.5 Git 背景

Git 最近修改时间、提交和作者只是背景证据。最近无人修改不代表无用，刚被
修改也不代表正确。Git 不可用时机械扫描继续，并清楚降级。

出于公开报告隐私边界，Phase 0 默认只输出最近修改时间和 Commit，不输出
作者名或邮箱。未来若增加作者字段，必须由配置显式开启并说明公开风险。

报告必须记录工作树是否有未提交变化。该字段只输出布尔值，不列出本地文件
名。工作树有变化不自动使扫描失效，但趋势解释必须看到这一事实。

## 5. 可靠状态

- `RELIABLE`：哨兵通过，配置的扫描面完整读取，所需环境可用。
- `PARTIAL`：哨兵通过，但存在明确的读取、大小或 Git 信息缺口。
- `UNRELIABLE`：哨兵失败；结果不得用于正式趋势或团队结论。

## 6. 输出契约

报告不得包含本机绝对仓库路径。头部至少包含版本、Schema、扫描时间、
Commit、分支、扫描器哈希、配置哈希、基线状态、可靠状态和 AI 状态。

每条 Finding 至少包含：

- 稳定 ID；
- Category；
- Source；
- Target（适用时）；
- 机械证据；
- 触发规则；
- 行号作为展示信息；
- 入站引用来源（适用时）；
- Git 最近修改背景；
- 已知限制；
- 人工复核提示。

输出使用稳定排序，不依赖文件系统遍历或哈希表偶然顺序。

## 7. 只读与输入安全

扫描器不得运行安装、构建、Hook、未知二进制、网络请求或自动 Git 提交。
只允许经过审查的只读 Git 查询。

Phase 0：

- 不跟随符号链接；
- 跳过配置排除目录；
- 跳过二进制和超大文件并标记 `PARTIAL`；
- 只扫描配置允许的文本后缀；
- 报告输出必须留在仓库根目录内。

Windows、子模块、Git LFS、动态消费者和完整 monorepo 语义尚未验证，不得
宣称支持完整。

## 8. 测试纪律

历史 C1-C6 是永久回归案例，详见
[`HISTORICAL_REGRESSIONS.zh-CN.md`](HISTORICAL_REGRESSIONS.zh-CN.md)。

改变引用解析、否定词、后缀、稳定 ID、自校验、报告 Schema 或趋势语义时，
必须同时更新夹具和测试。结构性变更必须使用只有变更后形态才会失败的负向
样本，不能拿原本完整的旧样本证明新门禁有效。

发布准备前必须让 RepoGC 扫描自身，但扫描结果不能触发自动清理。

## 9. 变更分级

- **A级**：表达与展示。检查 diff 和基本测试，不改变机械结果。
- **B级**：普通规则、配置、CLI 或报告字段。需要案例、夹具、测试和文档。
- **C级**：稳定 ID、基线、引用解析、自校验、可靠状态、Schema、趋势。
  需要迁移方案、新旧结果对比、用户知情和回滚。
- **D级**：自动删除、AI 裁决、删除 Gate 或契约、弱化自校验或人审。
  必须有独立设计、证据包、精确批准和专门验证；未经批准不得实施。

## 10. 日常流程

1. 检查目标、仓库指令、代码、测试、手册、报告、基线和 Git 状态。
2. 区分已知事实、尚未确认的假设和变更级别。
3. 选择最小、可回滚的根因修复。
4. 实现时保持确定性、离线和报告兼容。
5. 运行相关测试、C1-C6、自校验、自扫描和报告 Diff。
6. 对账计划、实际 diff、默认行为、Finding 数量和趋势口径。
7. 汇报结论、根因、修改、验证、风险和下一步。

## 11. 当前非目标

Phase 0 不做自动清理、通用 Code Review、AST 死代码分析、SAST、依赖或
License 扫描、Secret 扫描、云端平台、自动 PR、仓库总分和 AI 删除概率。

未来的 GC Roots、Typed Edges、Reachability 和 Mark-and-Sweep 只能生成
带证据路径的人工复核候选，不能执行 Sweep 删除。
